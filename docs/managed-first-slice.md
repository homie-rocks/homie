# Homie Managed: first-slice build plan

Companion to [the design](managed-design.md). Ship each row independently behind a managed-only flag. Keep free self-hosted builds independent of Homie. Do not recruit beyond the first venue until payment correctness, support and recovery are repeatable. Each step produces reviewable evidence; a completed implementation is not automatically permission to accept live money.

| Step | Small increment | Acceptance evidence |
| --- | --- | --- |
| 1 | Prove the existing studio on WFP: one synthetic tenant, dedicated D1, stable Table/Lobby namespaces, static assets, preview separation and dispatch routing. | Real deployed build, room reconnect, records/MCP access and function wake; guessed tenant IDs/bindings fail. Record V1 and provider versions. No live payments. |
| 2 | Add Artifacts source and the trusted deployment pipeline: push event, immutable build, isolated preview, release manifest and rollback. | Push edits one tenant; failed checks leave production serving; rollback retains D1/DO identities. Repo code cannot obtain deploy credentials. Read-only share token can clone but cannot push and is revocable. |
| 3 | Add Homie identity and resumable provisioning. | Owner signs in from a fresh browser, receives a working URL and limited agent principal without installs/keys/provider approvals. Crash/retry allocates one resource set; revoked membership fails. |
| 4 | Add Connect Accounts v2 onboarding and readiness states in sandbox. | Chosen responsibilities/full dashboard read back correctly; interrupted onboarding resumes; expired links refresh; capabilities gate selling. Test A2 and v2 account notifications. |
| 5 | Adapt catalog plan/verify to account-scoped direct-charge Payment Links and versioned fees. | Fixed-price seat carries correct fee; a donation has no fee; variable quantity/price is rejected for fee-bearing links. Owner sees processing versus Homie fees separately. |
| 6 | Build private webhook inbox, tenant delivery and reconciliation. | Signed sandbox payment produces one order/booking. Duplicate, late, out-of-order, wrong-account, wrong-mode and invalid-signature events cannot corrupt state. Restart after receipt loses no accepted event. |
| 7 | Ship the actual venue's recurring-event app and deterministic booking move. | Mobile booking and staff roster agree; concurrent last-seat purchases cannot oversell. Faults during pause/expire/move/resync remain recoverable; no success claimed while paused or uncertain. |
| 8 | Add the hosted Agent chat with read tools, constrained content edits and managed move tool. | Owner completes everyday tasks through conversation. Restart resumes work; stale versions and injected record text cannot grant authority. Bring-your-own AI uses existing scoped OAuth independently. |
| 9 | Add support console, takeover and private refund operation. | Owner asks for a human; agent mutations stop; duty operator sees context and resolves a sandbox refund once, including fee accounting. Audit covers every transition and backup operator escalation. |
| 10 | Add operational monitoring, MCP Events renewal and alerts. | Inject a Worker issue and a silent fulfillment failure; both create actionable incidents. Establish V2 coverage/fallback. Expired subscriptions, dead deliveries and failed payout simulation alert. |
| 11 | Add backup/export and restore/import runners. | Second operator restores into fresh resources, reconciles Stripe, avoids duplicate messages/refunds, and meets measured RPO/RTO. Export imports into a separate self-hosted account with no Homie runtime dependency or future fees. |
| 12 | Activate the real venue and observe four weekly cycles. | Legal entity and Canadian counsel/accountant review done, pilot venue named; platform/merchant live readiness, terms, safe tax setup and duty coverage verified. Real bookings and owner-directed changes, daily reconciliation, value baseline and support-time ledger. No founder rescue. |

Steps 4–11 may be developed against synthetic tenants but all must pass before step 12. Keep the first offer to one country/currency, fixed-price seats and dated recurring events. Custom domains, subscriptions, variable carts, external Stripe-account imports, broad autonomous code deployment and additional notification channels follow evidence from the pilot.

The release checklist is the acceptance column plus: no public verified-webhook bypass; no production bindings in CI; no cross-tenant data in agent context; tested fee-free self-hosted exit; and a named duty/backup operator. Run relevant existing studio booking, shop, functions, MCP and build checks when adapters change, then the managed integration scenarios above. Avoid repeating the entire game test suite for a control-plane-only change unless shared runtime behavior changed.

For each weekly pilot review record: successful workflows, owner time saved against baseline, paid/failed/refunded orders and fee totals, incident count, support minutes, restore age and actual infrastructure/model costs. Expand only after four successful cycles. The later proof is 20 organizations using Homie weekly with measured value, willing payment, sustainable support and recovery that another operator can perform.
